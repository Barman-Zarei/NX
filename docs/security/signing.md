# Signatures in NX (what they are and what NX has)
A digital signature proves a file was produced by the holder of a secret key and not modified. Different checks use different signatures:
1. **Secure Boot (firmware level).** UEFI firmware only runs boot files signed by a key it trusts (usually the Microsoft UEFI CA). Chain used by NX today: Microsoft-signed *shim* (signed by Microsoft for Canonical) -> Canonical-signed *GRUB* -> Canonical-signed *Linux kernel*. The kernel then enters "lockdown" mode. NX **re-uses Canonical's signed binaries**; it has NO signing key of its own, so it cannot sign its own kernels, GRUB or modules. Tested only in QEMU/OVMF with Microsoft keys pre-enrolled.
2. **Becoming independently Secure-Boot-capable** would require either (a) submitting an NX shim to the shim-review process so Microsoft signs it (months, strict requirements), or (b) users enrolling an NX key via MOK (Machine Owner Key) manually. Neither exists yet.
3. **Package signatures (APT).** Ubuntu repositories are signed by Ubuntu keys; debootstrap/apt verify them. NX has no repository of its own yet.
4. **Release signatures.** `*.sha256` files only detect corruption or a mismatched download; they are NOT signatures (anyone can publish a matching hash). A real NX release needs a detached GPG/minisign signature over the checksum file, with the public key published separately. Not done: no NX signing key exists, and no key may ever be stored in this repository.
